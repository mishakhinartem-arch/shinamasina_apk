## 3. Как запустить и протестировать

Рабочая копия на общей машине ботов: `/workspace/web-demo`.

```bash
# Локальный сервер (из этой папки)
python3 -m http.server 8765
# открыть http://localhost:8765/

# Юнит-тесты логики (без браузера)
node --test tests/logic.test.js
# или: npm test

# Сквозные сценарии + скриншоты в screens/
# нужен уже запущенный сервер на :8765, Chrome и зависимости tools/
cd tools && npm i && BASE=http://localhost:8765/ node e2e.js
```

Другой адрес сервера: `BASE=http://127.0.0.1:8765/ node e2e.js`.

Проверено 19.11.2026 (пачка v6): `node --test tests/logic.test.js` — **47/47** проходят; `cd tools && BASE=http://localhost:8781/ node e2e.js` — **все сценарии пройдены** (166 проверок; на пачке v5 было 41 тест и 156 проверок). Порт 8765 на общей машине ботов в этот прогон кто-то закрывал (сервер падал через несколько секунд), поэтому e2e гоняли на 8781 — адрес задаётся через `BASE`.

Документы (договор хранения и согласие на ПД): править оригиналы `/workspace/kassa-pravki/dogovor_hraneniya.md` и `soglasie.md` (копии лежат в `docs/`), затем `node tools/build-docs.js`. Шаблоны **юристом не проверены**.

После первой загрузки по **https** касса работает офлайн (service worker `sw.js`). На `http://localhost` SW не регистрируется.

## 4. Как публикуется

Публиковать **только** после явной команды Артёма «делай». Саму публикацию эта инструкция не запускает.

Обычный порядок, который использовался в этом проекте:

1. Правки в `/workspace/web-demo`, тесты зелёные.
2. Поднять версию кэша в `sw.js` (`const C = "shinamashina-web-demo-vN"`). На каждой публикации — новая версия, иначе посетители останутся на старом кэше. Список `FILES` в `sw.js` держать в синхроне с новыми скриптами и страницами.
3. Собрать zip (обычно кладут в `/workspace/uploads/`).
4. Залить в репозиторий https://github.com/mishakhinartem-arch/shinamasina_apk , ветка `main` (GitHub Pages).
5. Проверить, что Pages отдал новую версию `sw.js`, и предупредить Артёма: на планшете обновить страницу, лучше два раза.

Не пушить «заодно» и не выкладывать пачку без «делай».

Новый файл логики нужно добавить в HTML, в `sw.js` (`FILES`) и в `tests/load.js`.

## 6. Модель данных

Один объект состояния `S` в `localStorage` по ключу `SM.STORE_KEY` = `shinamashina_web_demo_v1` (имя ключа не менялось). Внутри поле `S.version`: сейчас **`SM.STATE_VERSION = 6`**.

Фото подписанных актов и шин хранятся отдельно: `shinamashina_web_demo_photo_<id>` (в демо место браузера ограничено). Между вкладками кассы / записи / киоска состояние подхватывается событием `storage`.

Миграции при `SM.load()`:

- **v5** — `SM.migrateV6` (js/store.js): `settings.surchargePct` → `runflatPct` (старое поле удаляется), `lowProfilePct = 20`; у заказов и чеков добавляется `lowprofile: false` (старые `runflat: true` остаются RunFlat, суммы старых чеков не пересчитываются); `SM.prices.ensureV6Prices` добавляет в `state.prices.extras` недостающие новые услуги и «Ремонт литого диска R14–R22» по названию и меняет «Вулканизацию бескамерной» с «от 1500» на «от 2000» **только если** владелец не менял 1500; цены владельца, скрытые позиции и свои услуги не трогаются; ставит `version = 6`.
- **v6 и новее** — оставляем, настройки сливаются с `SM.DEFAULT_SETTINGS` (новые ключи появляются, уже заданные не затираются).
- **v4** — `SM.warehouse.migrateRepairStock`: добавляет недостающие позиции ремонта и нормы, не удаляет и не перезаписывает заведённое, кастомные услуги `c:…` не трогает; собирает справочник поставщиков из названий в прошлых накладных (без ИНН/телефона); ставит `version = 5` и сразу сохраняет.
- **v3** — сначала `SM.clients.migrateV3` (список машин `cars[]`, история карточки, пересчёт «Переобувки» Газели 5 500 → 6 × «Итого за 1 колесо», если цену ещё не меняли), затем миграция склада v4→v5.
- **v1–v2, битое или пустое** — данные пересоздаются генератором `SM.seed()`.

Цепочка при загрузке: v3 → v4 → v5 → v6 за один раз. Важно: `ensureRepairStock` на уже существующих v5/v6 при загрузке **не вызывается**. Если позже понадобятся новые позиции ремонта у тех, кто уже на v5, нужна новая версия состояния.

Поля `S` и смысл каждого — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#состояние).

## 7. Бизнес-правила

Кратко то, что уже есть в коде и решено Артёмом. Формулы, функции и «почему» — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#бизнес-правила).

- **ЗП.** В каждом промежутке между приходами/уходами: выручка услуг периода × (личный % / число мастеров на смене) / 100. Округление до 50 ₽. Минимум 4 000 ₽ только при ≥ 8 ч по отметкам. Кто пришёл днём — считается с момента прихода. В базу % **не входят**: хранение, товары, позиция «Покраска» наряда (ответ Артёма 19.11). Правка дисков и услуги прайса внутри наряда покраски — в базе %. Аванс/премия/штраф — в расчётном листе; аванс из ящика уменьшает наличку.
- **Касса и смена.** Открытие с выбором мастеров (строки с выпадающим списком). Поле «Факт» при приходе — пересчёт ящика. Закрытие: всем «ушёл», ЗП вычитается из налички; не хватает — выдаём сколько есть, остальное в долг. Один день одному мастеру дважды не оплатить. Инкассация — только по PIN владельца (`SM.shift.collect`). Прошлые смены и история склада — под PIN. Мастер видит только свою «Моя ЗП за сегодня», чужие % в карточке заказа не показываются. % (5–60) правит только владелец в админке; неактивный сотрудник — в архиве и не предлагается на смену.
- **Скидки.** Постоянному 10% (настройка `loyaltyPct`) — автоматически, если у клиента уже есть хотя бы один оплаченный чек услуг; на все его машины одна скидка. Лимит кассира (по умолчанию 15% и 1 000 ₽, 0 = без ограничений) действует **только на ручную** скидку, не на постоянную. Скидки считаются от услуг + RunFlat, не от хранения, товаров и покраски.
- **Надбавки: RunFlat +20% и низкий профиль +20%** (v6, решение Артёма 19.11.2026; настройки `runflatPct` и `lowProfilePct`, правятся в Админке → «Настройки» → «Надбавки на монтаж»). Два отдельных переключателя в заказе (`o.runflat`, `o.lowprofile`; в чеке `r.runflat`, `r.lowprofile`, `r.totals.surchargeKind` / `surchargePct`). Если включены оба — действует **только большая**, они не складываются (при равных 20% итого +20%, не 40%). Надбавка идёт на строки «Монтаж», «Демонтаж», «Переобувка 4 колеса» / «Переобувка 6 колёс», «Итого за 1 колесо» целиком. Не на балансировку, «комплекс без смены резины», снятие/установку пакетом, ремонт и новые доп. услуги. «Как в прошлый раз» переносит оба флага.
- **Прайс v6.** Доп. услуги по ШиноМонстр (цены Артёма): медная смазка ступицы 50, зачистка ступицы (глубокая) 300, установка камеры 300, проверка камеры 100, замена вентиля 150, замена золотника 100, демонтаж секреток от 1000, демонтаж сложных болтов от 500, балансировка свыше 100 г (доплата) 100, установка датчика давления 300, удаление клейкой ленты с диска 300, снятие запасного колеса 200, боковой порез от 1500, дошиповка (1 шип) 25, замена шипа 35. «Вулканизация бескамерной» от 2000. «Ремонт литого диска» R14 от 1500, R15 от 1800, R16 от 2000, R17 от 2400, R18 от 2800, R19 от 3200, R20 от 3600, R21 от 4000, R22 от 4500 (за 1 диск, только литые; цену вводит кассир; на кассе виден только пункт выбранного радиуса, у позиции в прайсе поле `radiusOnly`). «Выездной шиномонтаж» не добавлялся. Ни одна из этих позиций не расходует склад (литые диски — в `W.REPAIR_SKIP`).
- **Типы авто.** Легковая, кроссовер, джип/микроавтобус, коммерческий (колонки R14C/R15C/R16C, кнопки только на R14–R16), Газель (только R16, 6 колёс). «Переобувка 6 колёс» = 6 × «Итого за 1 колесо» (в демо 6 × 1 025 = 6 150 ₽); если владелец уже менял старые 5 500 — не трогаем. «Снятие и установка 6 колёс» и «Комплекс без смены резины (6 колёс)» в прайсе уже на 6 колёс.
- **Очередь и посты.** В сезон по умолчанию 3 поста: 1–2 под онлайн-запись, 3-й под живую очередь. На посту одна машина. «Готова, ждёт оплаты» пост освобождает, машина остаётся в списке до оплаты. Живая очередь может занять свободный пост записи, если до ближайшей записи успеваем. Талоны с планшета — только в сезон, нумерация каждый день с №1; тот же госномер в тот же день (пока талон не «done») — тот же талон.
- **Ожидание** (`SM.live.waitMin`). Моделирование постов: занятый пост свободен в момент начала + время услуги (не раньше чем через 5 мин); записи на сегодня раскладываются по постам записи; машины впереди встают на самый ранний подходящий пост (с окнами до записи). Результат округляется вверх до 5 мин. Это ориентир, не обещание.
- **Онлайн-запись** — только 3 вида переобувки (названия для клиентов: полный шиномонтаж 40 мин, переобувка колёс на дисках 25 мин, снять/поставить 15 мин; время меняет владелец). Запись на ремонт — галочка владельца (`bookRepair`, по умолчанию выкл). Нужно согласие на ПД. В сезон вместимость слота = число постов записи.
- **Покраска.** Приём без оплаты, наряд в «Машины → В покраске», выдача — один чек на всё. Скидки на наряд не применяются. Покраска не входит в % мастеров и не в счётчик «Машины». Состояние дисков — галочки, печатаются в акте; «без повреждений» нельзя вместе с повреждениями.
- **Склад расходников.** Автосписание по нормам при оплате чека. Ключи норм: `r:` + услуга шиномонтажа, `f:` + название ремонта/мелочи (в прайсе у «Заплатка UP–4.5» типографское тире), `c:` + id своей услуги, `gift`. Грузики (`box: true`) — только целыми коробками, без норм и автосписания; кнопка «Взять коробку». Цена закупки при приходе — средневзвешенная; `cost === 0` значит **«не задана»**, не выдумывать цену, в админке подсказка «укажите цену закупки». Предупреждения «заканчивается» — только на `owner.html`, с кассы убраны. История движений склада — под PIN.
- **Склад ремонта (v5, локально, на сайт не выкладывалось).** На склад добавлены позиции из `prices.repair.items` и ремонтные услуги из «Мелочей», кроме вулканизации, правки дисков и ремонта камеры (`W.REPAIR_SKIP`): заплатки R-8, R-10, R-11, R-12, R-13, R-14, R-15, R-18, R-20, R-25, грибки №4 и №9, ножка грибка №9. Норма 1 шт на услугу, плюс `f:Ремонт жгутом` → жгут, `f:Ремонт грибком` → Грибок №7. Новые позиции: закупка 0 («не задана»), минимум 5. Уже заведённые (жгут, Грибок №7, Заплатка UP-4.5) не дублируются и не перезаписываются. Свои услуги (`c:…`) миграция не трогает.
- **«Расходует со склада» (v5).** В окне услуги (Админка → «Услуги и товары», и для своих, и для встроенных) блок материалов: поиск позиции склада по первым буквам, количество на 1 услугу, «＋ Новая позиция склада» прямо из окна (закупка 0 — «не задана»). Грузики (коробки) не привязываются. Если у своей услуги нет нормы — в окне и в списке подсказка «нет нормы списания», в Админке → «Склад» общий список таких услуг. Сохраняет `W.setServiceUses` (заменяет нормы услуги целиком).
- **Поставщики (v5).** Справочник `S.warehouse.suppliers`: название, ИНН (10 или 12 цифр, можно пусто), телефон, способ оплаты «Наличные» / «Безнал». В приходе по накладной поставщик подсказывается по первым буквам (любое слово названия, ИНН или телефон); выбор подставляет ИНН, телефон и оплату; нового поставщика заводит сам приход. Способ оплаты — **только отметка** в накладной (`doc.pay`), из кассы и ящика ничего не вычитается (решение Артёма 19.11 16:05).
- **Приёмка в одно нажатие (v5).** На карточках постов записи (1 и 2) крупно подсвечена следующая машина по записи: госномер, время, имя, вид работ (`SM.booking.nextForPosts`: ближайшие записи раздаются сначала свободным постам, потом занятым). На свободном посту кнопка «Принять № …» — сразу ставит машину на этот пост и открывает заказ с клиентом, радиусом/типом машины и услугой из записи (полный шиномонтаж → «Переобувка 4 колеса», на дисках → «Комплекс без смены резины», снять/поставить → «Снятие и установка 4-х колёс»; цена только из прайса, без радиуса услуга не подставляется). «Следующий» в живой очереди ставит машину на свободный пост и сразу открывает заказ (`SM.live.acceptNext`); отдельного шага «Вызваны — принять машину» больше нет, карточка называется «На постах из очереди».
- **Товары** (`SM.products`) — отдельные от расходников. В чеке без скидок, не в % мастеров, при оплате списываются. Нельзя положить в заказ больше остатка. Добавление/правка/скрытие — по PIN.
- **Хранение.** Фиксированный тариф владельца: ₽ за комплект 4 шины за сезон (по умолчанию 6 мес.) по радиусу + доплата за диски; другой срок или число шин — пропорционально, округление до 50 ₽. **Демо-ставки примерные.** Цена подставляется сама; вручную вне тарифа — только по PIN. Скидки не действуют, в базу % не входит, в отчётах — отдельной строкой. Комментарий и необязательное фото шин. Договор и согласие — шаблоны, юристом не проверены.
- **Клиенты.** Один телефон — несколько машин (госномер, марка, размер, давление перед/зад). Поиск по госномеру или средним 3 цифрам сразу выбирает машину; по телефону/имени, если машин несколько, спрашиваем какая. Карточка правится без PIN; каждое изменение «было → стало», кто на смене и когда — в карточке и у владельца. Телефон везде с «+7». Давление: цифры `22` → `2.2`, диапазон 1.0–6.0. Анкета киоска: известный телефон дополняет карточку; чужой госномер на другом телефоне — «подойдите к администратору».
- **Напоминания.** Канал клиента MAX / Telegram / SMS + согласие; за 24 ч и за 2 ч до визита, пока открыта касса или страница владельца. Журнал — у владельца. В демо статус «отправлено (имитация)». Реальную отправку не подключать без отдельного «да» (платный SMS — только после «да»).
- **Принтер талонов.** IP/порт в настройках, тестовая печать. Из браузера TCP недоступен — честное сообщение и образец ленты. Печать только из APK: `window.AndroidPrinter.print(ip, port, base64)`, ESC/POS, CP866. На живом принтере **не проверялось**.
- **Оплаты в демо:** наличные (в ящик), карта, QR/СБП. Эвотор не подключён.
- **Прибыль в отчёте:** выручка − начисленная ЗП (смены + премии − штрафы; аванс — выплата, не расход) − расходы − себестоимость расходников − закупка проданных товаров. Постоянный расход, если число месяца уже прошло, по умолчанию начинается со следующего месяца (можно «с этого месяца»).
